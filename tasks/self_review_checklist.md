# 自己レビュー チェックリスト (Codex に投げる前の「突っ込みリスト」)

作成日: 2026-04-11
用途: Claude Code が設計書・実装を Codex adversarial review に投げる前に自分で通す。v1〜v3 の NO-GO ループを招いた「自分で気づけたはずの穴」を再発させないための固定手順。
使用タイミング: **設計書提出前 / 実装 PR 提出前**。必須。スキップ禁止。

---

## 使い方

- 各項目に対し「YES / NO / N/A」を明示する
- 「YES だが自信がない」はダメ、証拠を書く (ファイル:行番号、実測ログ、rg 結果など)
- 1 項目でも NO が残るなら Codex に出さずに直す
- N/A を使う場合は理由を添える (例: 「本 Step は read-only なので不要」)
- チェック結果は **設計書 / PR 本文の末尾にコピペ** して Codex にも見せる

- [ ] **§0-2**: 本変更が触るファイル・ディレクトリを列挙したか? 追加・変更・削除を種別ごとに分けて書く

## §1. 網羅性チェック (Codex v1〜v3 で繰り返し指摘された最大カテゴリ)

### §1-1. マトリクス宣言と実体の一致

- [ ] **§1-1a**: 「全フィールド × 全パターン網羅」と書いたか? 書いた場合、**実際のテスト一覧がその直積になっているか** 行数を数えて確認したか?
- [ ] **§1-1b**: 「代表値テスト」と「網羅テスト」を言葉で分けたか? 代表値なら「代表値 (N/M フィールド × K/L パターン)」と明記
- [ ] **§1-1c**: テーブルの宣言と、実装される関数 / テストの命名 / 件数が 100% 一致するか?

### §1-2. プラットフォーム横断 edge case

- [ ] **§1-2a**: Windows / POSIX 両方で動くコードなら、両方の Path 処理を適用したか? (`PureWindowsPath` + `PurePosixPath`)
- [ ] **§1-2b**: UNC (`\\server\share`), drive-relative (`C:foo`), root-relative (`\foo`), backslash traversal (`..\foo`), forward traversal (`../foo`), 全角空白・BOM・CRLF, cp932 圏外文字 — 関連する全パターンを列挙したか?
- [ ] **§1-2c**: 「Python の `Path` は絶対パスだけ弾けばいい」と思ったら、PureWindowsPath の edge case をもう一度見直したか?

### §1-3. 実測と設計の対応

- [ ] **§1-3a**: 実測スクリプト (probe) は、本当に設計で採る方式と**同じ順序・同じ sys.modules 操作・同じ import 方法** を再現しているか?
- [ ] **§1-3b**: probe で使っているダミーモジュールは、実設計の from-import / sys.modules 注入 / cleanup sequence を**全部**カバーしているか?
- [ ] **§1-3c**: 「AAA で動いたから BBB でも動く」と類推で済ませていないか? BBB も実測したか?

## §2. 契約の完全性

- [ ] **§2-1**: 関数の契約 (入力型 / 出力型 / 失敗時の挙動 / 副作用 / 純粋性) を 1 行で書けるか?

## §3. 既存システム制約 (本プロジェクト固有)

- [ ] **§3-1 cp932**: Python ソースに絵文字・em-dash・全角英数・cp932 圏外文字が混入していないか? `print()` に日本語だけ許容、絵文字禁止
- [ ] **§3-2 ffmpeg コマンド長**: ffmpeg を呼ぶ変更の場合、コマンド長 8192 超過を見積もったか? (WinError 206)
- [ ] **§3-3 WSL/Windows path 変換**: `/mnt/c/...` と `C:\...` の混在が発生する箇所を列挙したか? `cygpath` 呼び出しが潜んでいないか?
- [ ] **§3-4 Gemini rate limit**: Gemini API を叩くなら retry / backoff / quota の明示ポリシーがあるか?
- [ ] **§3-5 一時ファイルロック**: 並行実行で競合するファイルがあるなら flock / msvcrt の明示利用があるか?
- [ ] **§3-6 scripts/secrets.py shadowing**: sys.path[0] が scripts/ になる実行パスを作っていないか? `cd scripts && python ...` パターンは禁止
- [ ] **§3-7 Task Scheduler 連動**: 10:00 定時タスクが参照するファイル (`run.bat`, `generator.py`, `skill_*.py`) を 1 文字でも変えていないか?
- [ ] **§3-8 self_healing 破壊経路**: `_fix_delete_token_reauth` / `_fix_kill_orphan_processes` / `_fix_delete_temp_files` に関わる変更か? 関わるなら scope から外すか user 承認必須
- [ ] **§3-9 pickle / module cache**: 既存モジュール名・階層・`__init__.py` を変更していないか? pickle キャッシュが破れる可能性があるか?

## 使用記録

このチェックリストを使った時は、設計書 / PR 本文の末尾に以下の形式で記録する:

```
## 自己レビューチェックリスト適用結果 (tasks/self_review_checklist.md)

- §0: [YES/NO/N/A + 根拠]
- §1-1: [YES/NO/N/A + 根拠]
- §1-2: ...
- (以下全項目)

NG だった項目と対処: [なし / 列挙]
Codex に送るかどうか: [送る / 送らない (理由)]
```

## 本チェックリストの更新方針

- Codex レビューで新しい指摘パターンが出たら、そのカテゴリを本リストに追加する
- 3 回以上繰り返される指摘は **§1〜§7 の該当節を強化** する
- 項目が 100 を超えたらカテゴリ統合を検討する
- v1〜v3 NO-GO の個別指摘を引き当てられているかを月 1 回振り返る
